# 项目更新说明（2026-10-16）

1）光线接收器

持续接收器接通、断光时分别切换一次关联门；持续照射不重复切换。永久接收器保持首次照射后锁定。接收器与拉杆共用关联组时，各次状态变化依次作用于门。

2）发射器与门

可推动发射器能够逐格推入、推出已开启的门所在格。关闭的门仍阻挡推动。占据门格期间，同时保留发射器和门的数据，不丢失门的关联、编号显示、颜色与朝向。

门的基础开关动画、四个朝向、推动过程中的动画保持和反向关闭已通过自动测试；未复现独立的门动画故障。具体关卡画面仍待人工验收。

3）切割机

禁用切割机的 F 气泡及 F 按键切割。保留大史莱姆按正确方向移动进入时自动切割，四个朝向均已验证。

4）同步滑行与融合

冰史莱姆不再按同伴起步前的位置截断滑行路线。同步移动时可继续追赶，并在实际进入同一格后自动融合。

同伴正在离开的旧格不触发融合；加速先到共同目的格时停下，待同伴实际到达后融合。融合后清空剩余路线，停用被合并角色，保留当前操作角色的控制权。

5）规则确认

满足条件的小史莱姆通过碰撞自动融合，F 不是必要条件；误触沿用 Z 撤回。

机关显示编号从 1 开始连续排列，删除后重新整理，实际关联使用独立的 linkId。此前两项与这些规则冲突的旧测试已修正。

6）存档与撤回

新增运行时 coveredBlocks 数据，保存发射器占据门格时的门信息；旧地图缺少该字段时按空数据处理。

机关进度增加 blockId，区分同格的门与发射器。恢复时先还原门状态，再重算光路，避免额外触发信号。融合前的进度可恢复为两只小史莱姆。

7）结构调整

（1）新增 Runtime/BlockWorld.Passage.cs：处理占据门格时的数据保留与恢复。

（2）新增 Runtime/Gameplay/Player/SlimePartyController.Fusion.cs：集中处理融合条件、移动同伴、控制权与路线结束。

（3）新增 Tests/Editor/SynchronousFusionTests.cs，并补充光线、门、切割和存档回归测试。

以上路径均相对于 Tools/BlockMapEditor。地编 README 已更新操作、关联、编号和交互说明。
